You will see “Windows protected your PC” the first time you run it. Click More info, then Run anyway.

Your Mac will say the app is damaged

It is not. macOS marks anything downloaded from the internet, and for an app without a paid Apple certificate it words that badly.

Drag the app to Applications, then paste this into Terminal once:

xattr -dr com.apple.quarantine "/Applications/{{APP_NAME}}.app"

That clears the download mark on this one app. It changes no system setting and turns nothing off.

The same two steps fix an update that fails with Read-only file system. That means the app is running from the disk image, or from the locked temporary copy macOS uses while it is still marked as downloaded — and neither of those can be written to, so it cannot replace itself.

Is it safe

You do not have to take our word for it

You are downloading a program from strangers on the internet. Being careful about that is the right instinct, so here is everything you need to check us.

The code is public

The launcher and the Java it installs are on GitHub in full. Read it, build it yourself, or rebuild the patch and check it matches what we signed, class for class.

See the code

Nothing unsigned gets in

Every file we send carries our signature. The launcher checks each one before it lands on your PC and refuses anything that does not match.

It leaves your game alone

It changes one file in Project Zomboid while you play and puts it back when you quit. If it ever crashes, it repairs that file the next time you open it.

It stays out of everything else

No background service, nothing at startup, no other games touched. It reads your Steam ID and where the game is installed. That is all.

For the curious

Check what you downloaded

You do not have to trust us on any of this. Every claim below is something you can check yourself, and the tools to do it ship in the repository.

Compare it against your own copy. Every platform's checksum is listed in SHA256SUMS.txt.

The patch it installs

The Java the launcher puts into your game is listed in a manifest signed with this key. It is compiled into the launcher, so this is the key it really uses:

{{RELEASE_PUBKEY}}

From a copy of the repository, this checks the signature and every one of the {{PAYLOAD_FILES}} files against it:

node tools/verify-release.mjs

That the patch really is the published source

A signature says who published a file, not what is inside it. We do not compile the patch ourselves: GitHub Actions compiles it from a public commit and signs a statement saying so. This checks that statement and that every class the manifest lists is one GitHub built:

node tools/verify-provenance.mjs

Or rebuild it yourself and compare byte for byte. The manifest names the exact commit and JDK, so there is no guessing which version you are checking against:

.\tools\reproduce-payload.ps1

You can also disassemble any single class and diff it against the untouched one in your own copy of the game:

.\tools\inspect-class.ps1 zombie.ZomboidGlobals

That the installer was built from that source

The installers are built by GitHub Actions too. With the GitHub CLI installed:

gh attestation verify {{INSTALLER}} --repo {{SOURCE_REPO}}

What this does not prove

An attestation proves which public commit GitHub built a file from. It does not prove that commit is harmless: that is what reading the source is for.

The server's mod content is not in that repository either. What is published there is the launcher and the Java patch it installs on your machine.
